# 2차 설계안 — 교정 이력 + 교정 성적서

- 작성일: 2026-08-27
- 상태: **승인 대기**
- 1차 설계는 [DESIGN.md](../DESIGN.md) 참고

---

## 1. 무엇을 만드나

지금은 계측기마다 **교정 기한 한 칸**만 있다. 교정을 새로 받으면 그 칸을 덮어쓰게 되고,
언제 어디서 교정받았는지는 남지 않는다.

2차에서는 두 가지를 만든다.

1. **교정 이력** — 교정할 때마다 기록이 쌓인다. 2020년부터 지금까지의 이력을 성적서에서 뽑아 채운다.
2. **교정 성적서** — PDF 를 올리고, 목록에서 바로 열어볼 수 있게 한다.

## 2. 성적서 자동 연결 — 실제로 조사한 결과

NAS 의 성적서 **350건**을 계측기 79대에 붙여 봤다.

| 방법 | 붙는 건수 |
|---|---|
| 파일명의 **S/N** 으로 (예: `... (289) (42050017).pdf`) | 162건 |
| 파일명의 **BNB 번호**로 (예: `BNB014_250131.pdf`) | **113건 추가** |
| **합계** | **275 / 350건 (79%)** |

### BNB 번호가 열쇠였다

교정 업체가 계측기마다 **고정된 관리번호**(`BNB001`, `BNB014` …)를 매기고 있다.
연도가 바뀌어도 같은 계측기는 같은 번호다.

```
BNB014 → DS0043 (FLUKE 289, S/N 42050017)
  2022년  Copies_BNB014-220120B01-015 ( 289_42050017 ).pdf
  2023년  Copies_BNB014-230119B01-029 (289) (42050017).pdf
  2025년  Copies_BNB014-250123B01-035 (289) (42050017).pdf
  2026년  Copies_BNB014-260120B01-026 (289) (42050017).pdf
```

**41개 번호를 뽑았고 충돌이 하나도 없었다.** 즉 이 표는 믿을 수 있다.
S/N 이 파일명에 있는 해(2022·2023·2025·2026)에서 표를 만들고,
S/N 이 없는 해(2020·2021·2024)의 파일에 그 표를 적용하는 방식이다.

이 `BNB` 번호는 계측기 정보에도 **교정업체 관리번호**로 함께 저장한다.
앞으로 성적서를 올릴 때 자동 연결에 쓰인다.

### 못 붙는 75건

대부분 **2020년 파일**이다. 파일명에 S/N 도 없고, 그 BNB 번호가 다른 해에 한 번도
S/N 과 함께 나타나지 않아 어느 계측기인지 알 수 없다.

→ **버리지 않는다.** "주인 없는 성적서" 목록으로 남겨두고, 화면에서 계측기를 지정하면 붙는다.

## 3. 데이터 구조 — 표 두 개 추가

### `web_meter_calibrations` — 교정 이력

| 컬럼 | 예시값 | 설명 |
|---|---|---|
| `id` | uuid | |
| `meter_id` | → web_meters | 어느 계측기 |
| `calibrated_on` | `2026-01-20` | **교정받은 날.** 성적서 파일명에 날짜가 있어 정확히 알 수 있다 |
| `next_due_ym` | `2027-01` | 이 교정으로 정해진 다음 기한 |
| `agency` | `BNB` | 교정 기관 |
| `certificate_no` | `BNB014-260120B01-026` | 성적서 번호 |
| `result` | `PASS` | `PASS` 합격 / `FAIL` 부적합 / `UNKNOWN` 모름 |
| `note` | | 비고 |
| 소프트 삭제 4종 + 시각 | | |

> **교정일만 "일"까지 저장하는 이유**: 교정 기한은 년·월로 관리하기로 했지만,
> 실제로 교정받은 날은 성적서에 정확히 찍혀 있다. 있는 정보를 굳이 버릴 이유가 없다.
> 화면에는 `2026-01-20` 으로 보이고, 기한은 그대로 `2027-01` 이다.

**교정 이력을 등록하면 계측기의 교정 기한이 자동으로 갱신된다.**
가장 최근 교정의 `next_due_ym` 이 계측기의 `calibration_due_ym` 이 된다.
지금처럼 두 군데를 따로 고치지 않아도 된다.

### `web_meter_certificates` — 성적서 파일

| 컬럼 | 설명 |
|---|---|
| `id` | uuid |
| `meter_id` | 어느 계측기 (**null 허용** — 주인 없는 성적서 75건) |
| `calibration_id` | 어느 교정 건 (null 허용) |
| `file_path` | 상대경로 `meters/<계측기uuid>/certs/<파일uuid>.pdf` |
| `original_name` | 원본 파일명 (`Copies_BNB014-...pdf`) — 검색에 쓴다 |
| `mime_type` · `size_bytes` | |
| `source` | `IMPORT`(NAS 이관) / `UPLOAD`(화면 등록) |
| 소프트 삭제 4종 + 시각 | |

### 계측기 표에 한 칸 추가

| 컬럼 | 설명 |
|---|---|
| `agency_no` | 교정업체 관리번호 (`BNB014`). 앞으로 성적서 자동 연결에 쓴다 |

## 4. 화면

### 계측기 상세 — 아래쪽에 이력이 붙는다

```
┌──────────────────────────────────────────────────────────────┐
│  DS0043  TRUE RMS MULTIMETER                    ● 사용중      │
│  ... (지금 있는 정보 + 사진) ...                              │
├──────────────────────────────────────────────────────────────┤
│  교정 이력                                   [+ 교정 등록]관리자│
├──────────────────────────────────────────────────────────────┤
│  2026-01-20   다음 기한 2027-01   BNB   합격    📄 성적서      │
│  2025-01-23   다음 기한 2026-01   BNB   합격    📄 성적서      │
│  2023-01-19   다음 기한 2024-01   BNB   합격    📄 성적서      │
│  2022-01-20   다음 기한 2023-01   BNB   합격    📄 성적서      │
├──────────────────────────────────────────────────────────────┤
│  성적서                                      [+ 파일 올리기]관리자│
│  📄 Copies_BNB014-260120B01-026 (289) (42050017).pdf  1.2MB   │
└──────────────────────────────────────────────────────────────┘
```

- **📄 를 누르면 PDF 가 새 탭에서 열린다.** 로그인한 사람만 볼 수 있다.
- 이력은 최근 것이 위로 온다.
- 교정 등록/성적서 올리기는 **관리자만**. 열람은 전 직원.

### 목록 화면 — 성적서 있는 계측기 표시

계측기명 옆에 작은 📄 표시. 누르면 상세로 간다.

### 주인 없는 성적서 `/certificates/unassigned` — 관리자만

자동으로 못 붙인 75건의 목록. 계측기를 골라 붙일 수 있다.

## 5. 파일 올리기 — 방식과 보안

### 스트림으로 받는다

`request.formData()` 는 파일 전체를 메모리에 올린다. NAS(DS218+)는 RAM 이 작아
성적서 여러 개를 동시에 올리면 위험하다.

→ 브라우저에서 파일을 **요청 본문에 그대로** 실어 보내고(`PUT`), 서버는 스트림으로 디스크에 쓴다.
추가 라이브러리가 필요 없고 메모리도 안 먹는다.

```
PUT /api/meters/<id>/certificates?name=<파일명>
본문: 파일 그 자체
```

### 검사 항목

| 검사 | 내용 |
|---|---|
| 확장자 | **PDF · JPG · PNG 만** 허용. 나머지 전부 거부 |
| 매직넘버 | 파일 앞부분을 읽어 확장자와 맞는지 확인 (`%PDF-` 등) |
| 실행 파일 | `MZ`(Windows) · `ELF`(Linux) 헤더는 **어떤 확장자로 위장해도 거부** |
| 브라우저가 보낸 MIME | **믿지 않는다.** 매직넘버로 다시 정한다 |
| 크기 | 1건당 **최대 20MB** |
| 저장 순서 | **파일 먼저, DB 기록 나중** |
| 내려줄 때 | 앱을 거쳐 권한 검사 후 스트림. `nosniff` 부착. 한글 파일명은 `filename*=UTF-8` |

### 저장 위치

```
C:/WEB-DATA/dss-meters/
└─ meters/<계측기uuid>/
   ├─ <사진uuid>.jpg          ← 지금 있는 사진
   └─ certs/<성적서uuid>.pdf   ← 새로 추가
```

디스크 파일명은 UUID. 원본 파일명은 DB 에만 둔다. **백업 스크립트는 그대로 두면 된다** —
`FILE_STORAGE_ROOT` 아래를 통째로 미러하므로 성적서도 자동으로 백업된다.

## 6. 과거 성적서 이관 (NAS → 시스템)

```
npm run import-certs           보기만 하고 아무것도 바꾸지 않음 (검토용)
npm run import-certs -- --apply  실제로 넣음
```

1. NAS 의 성적서 350건을 읽는다 (**원본은 건드리지 않는다. 복사만 한다**)
2. S/N → BNB 번호 순서로 계측기를 찾는다
3. 파일명에서 교정 날짜를 뽑아 **교정 이력 163건**을 만든다
4. PDF 를 저장소로 복사하고 성적서 기록을 만든다
5. 못 붙인 75건은 **주인 없는 성적서**로 넣는다
6. 결과를 표로 출력한다

> **먼저 `--apply` 없이 돌려서 결과를 보여드리고, 확인받은 뒤에 실제로 넣겠습니다.**

예상 용량: 126MB (지금 사진 6.5MB + 성적서 126MB = 약 133MB)

## 7. 만들지 않는 것

- ❌ 성적서 PDF 안의 **측정값 읽기** — 사람이 열어 본다
- ❌ 교정 업체 발주·견적 관리
- ❌ 교정 일정 자동 계획
- ❌ 성적서 미리보기 화면 (브라우저 기본 PDF 뷰어로 충분하다)
- ❌ 2020년 성적서 75건의 **자동 연결** — 근거가 없다. 화면에서 사람이 붙인다

## 8. 확인이 필요한 것

1. **교정일을 "일"까지 저장** — 성적서에 날짜가 있으니 정확히 기록하려 한다.
   기한(년·월)과는 별개다. 괜찮은가?
2. **`result`(합격/부적합)** 칸을 둘까? 성적서 파일명에는 없어서 이관 시에는 전부 `모름` 으로 들어간다.
   앞으로 등록할 때만 고르게 된다. 필요 없으면 뺀다.
3. **DS0060 과 DS5060 이 S/N 이 같다** (`MF120131-01B`, NOA-10K2R0Z).
   한쪽은 DSS 자산, 한쪽은 교산 자산으로 등록되어 있다.
   같은 물건이 두 번 등록된 것인가, 아니면 S/N 오기인가?
   → 이것 때문에 성적서 2건이 어느 쪽인지 정하지 못하고 있다.
