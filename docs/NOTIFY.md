# 교정 기한 알림 메일

교정 기한이 **다음 달**인 계측기를 매달 **1일**에 메일로 알린다.
기한이 닥쳐서 알리면 교정을 보낼 시간이 없기 때문이다.

예) 기한이 `2027-02` 인 계측기 → `2027-01-01` 에 발송

---

## 화면에서 하는 일

**관리자 머리말의 「알림 설정」** → http://localhost:3200/settings/notify

| | 내용 |
|---|---|
| 받는 사람 | 메일 주소·이름·**받을 언어**(한국어/日本語)를 등록한다. 잠시 끄고 켤 수 있다 |
| 메일 문구 | 제목 · 표 위에 오는 말 · 표 아래에 오는 말을 언어별로 고친다 |
| 발송 기록 | 언제 어느 기한을 몇 대·몇 명에게 보냈는지 |

### 문구의 자리표시자

문구 안에 두 개를 쓸 수 있다. 그 외는 그냥 글자로 나간다.

| | 바뀌는 값 |
|---|---|
| `{ym}` | 알리는 기한 (`2027-01`) |
| `{count}` | 계측기 대수 |

**계측기 표는 문구가 아니라 데이터라 자동으로 붙는다.** 화면에서 고치는 것은 말뿐이다.
입력하는 즉시 아래에 채워진 모습이 보이므로, 저장 전에 확인할 수 있다.

문구를 한 번도 저장하지 않았으면 코드의 기본 문구를 쓴다
(`src/lib/mail/template.ts`). 저장한 문구를 지우고 기본으로 되돌리려면
그 언어의 행을 지우면 된다.

---

## 누가 받는가

받는 사람으로 등록되고 **「받음」 상태인 사람**만 받는다. 한 명도 없으면 메일을 만들지 않는다.

받는 사람마다 언어가 따로다. 교산 담당자를 넣으면 그 사람만 일본어로 받는다.

## 무엇이 알림 대상인가

교정 기한이 그 달인 계측기 중, 아래 **네 상태는 빼고** 보낸다.

| 빼는 상태 | 왜 |
|---|---|
| 교정대상아님 | 더미로드 등 — 애초에 교정을 받지 않는다 |
| 고장(교정불가) | 고쳐서 쓸 수 없다 |
| 반납·발송 | 이미 교산으로 돌려보냈다 |
| 교정진행중 | 이미 교정 업체에 보냈다 — 또 알리면 잔소리가 된다 |

이 판단은 `src/lib/notify.ts` 의 `NOT_NOTIFIED` 한 곳에 있다.

## 매일 자동으로 돌아간다 (Windows 작업 스케줄러)

**이미 등록되어 있다.** 손댈 것이 없다.

| 항목 | 값 |
|---|---|
| 작업 이름 | `계측기 교정기한 알림 메일` |
| 실행 시각 | **매일 09:00** |
| 실행 내용 | `npm run send-notify` (시작 위치 `C:\Users\이남준\dss-meters`) |
| 놓친 실행 | PC 가 꺼져 있었으면 다음에 켤 때 자동으로 실행한다 |
| 실패 시 | 15분 뒤 최대 2번까지 다시 시도한다 |

**매일 돌지만 실제로 나가는 것은 1일뿐이다.** 1일이 아니면 아무것도 하지 않고 끝난다.
날짜 판단을 스케줄러가 아니라 코드가 하는 이유는, 스케줄러 설정이 어딘가에서
조용히 바뀌어도 규칙은 코드에 남아 있게 하기 위해서다.

**같은 기한은 두 번 보내지 않는다.** `web_notifications` 에 성공 기록이 있으면 건너뛴다.

### ⚠ PostgreSQL 이 꺼져 있으면 메일도 못 나간다

PostgreSQL 이 서비스로 등록되어 있지 않아, PC 를 껐다 켜면 사람이 직접 켜야 한다.
꺼진 채로 1일 09:00 이 되면 알림이 그냥 넘어간다. 자동으로 켜지게 하는 방법은
docs/BACKUP.md 의 "PostgreSQL 이 꺼져 있으면 백업이 실패한다" 를 보라.

이 경우 `logs\notify.log` 에 실패로 남고, 발송 기록에는 아무것도 안 남는다.
못 보낸 달은 나중에 이렇게 보낼 수 있다.

```
npm run send-notify -- --ym=2027-02 --force
```

### 잘 돌고 있는지 보려면

```powershell
Get-ScheduledTaskInfo -TaskName '계측기 교정기한 알림 메일'
```

`LastTaskResult` 가 **0** 이면 성공이다.

### 실행 로그

매번 `logs\notify.log` 에 쌓인다. 1일이 아니라 그냥 끝난 날도 남는다 —
"돌기는 했는지" 를 나중에 알 수 있어야 하기 때문이다.

```
type "C:\Users\이남준\dss-meters\logs\notify.log"
```

> 이 로그는 이 PC 에만 남는다 (git 에 올라가지 않는다).


## 메일 서버 (cafe24)

값은 `.env.local` 에 있다. 웹메일의 **「환경설정 → POP3/SMTP 사용설정」** 화면에 적힌 그대로다.

| | 값 |
|---|---|
| SMTP_HOST | `smtp.cafe24.com` |
| SMTP_PORT | `587` |
| SMTP_USER | 메일 주소 전체 |

### 알아 둘 것

- **465 포트는 열려 있지 않다.** 587 로 붙어 STARTTLS 로 올린다.
- cafe24 서버가 **TLSv1 까지만** 하고 RFC 5746(안전한 재협상)을 지원하지 않는다.
  요즘 Node 는 이런 서버를 기본으로 거절하므로 `src/lib/mail/transport.ts` 에서
  예외를 열어 두었다. 사내에서 우리 메일 서버로만 나가는 연결이라 이 정도로 둔다.
- 웹메일 화면에서 **SMTP 연결이 '사용함'** 이어야 로그인이 된다.
- **비밀번호를 바꾸면 서버에 반영될 때까지 최대 30분쯤 걸린다.**
  바꾼 직후에는 `check-smtp` 가 535 로 실패하는 것이 정상이다.
- `smtp.cafe24.com` 은 서버 3대로 분산되어 있다. 반영 시점이 서버마다 다를 수 있다.

### 안 될 때

```
npm run check-smtp
```

`535` 가 뜨면 이 순서로 본다.

1. 웹메일에 그 비밀번호로 직접 로그인이 되는지
2. 환경설정 → POP3/SMTP 사용설정 에서 SMTP 연결이 '사용함' 인지
3. 비밀번호를 방금 바꿨다면 30분쯤 기다렸다가 다시
